## What to build

직원은 본인의 대여·반납 이력을 확인하고, 관리자는 전체 직원의 사용 중·반납 대기·완료·연체 현황을 한 화면에서 확인한다.

## Acceptance criteria

- [ ] 본인 이력과 관리자 전체 현황·상세 화면을 API·SQLite에 연결한다.
- [ ] 자산·사용자·반납 예정일·처리 상태·사유·처리 시각을 권한 범위에 맞게 표시한다.
- [ ] KST 반납 예정일 23:59:59까지를 기한으로 하고 이후 반납 완료되지 않은 대여를 연체 표시한다.
- [ ] 반납 확인 대기도 연체 판단에 포함하고 완료 이후 현재 연체로 표시하지 않는다.
- [ ] 연체에 따른 자동 반납·이용 차단·이메일·메신저 발송은 하지 않는다.
- [ ] 직원은 요청 식별자를 바꾸어도 다른 직원 이력을 볼 수 없다.
- [ ] KST 경계 시각·다른 브라우저 시간대·반납 대기 연체·권한을 실제 API·SQLite 통합 테스트로 검증한다.
- [ ] 빈 이력·오류·로딩 상태와 PR 빌드·테스트를 확인한다.
