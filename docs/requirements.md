# 요구사항

## 인증

- Google 계정 로그인만 제공한다.
- 관리자가 미리 등록한 이메일만 로그인할 수 있다.
- 최초 관리자 지정 방식과 관리자 이메일은 추후 사용자가 정한다.
- 개발은 테스트 직원 1명과 테스트 관리자 1명으로 진행한다. 직원 이메일 등록·비활성화 관리 화면(#3)은 사용자 요청으로 제외하며 운영 허용 계정은 최종 배포 설정으로 연결한다.

## 대여와 반납

- 직원이 개별 자산을 선택해 대여를 신청한다.
- 관리자 한 명이 승인하면 즉시 대여가 시작된다. 별도 인도 확정 단계는 없다.
- 같은 자산에 여러 직원의 대여 신청을 허용한다. 한 건을 승인하면 해당 자산의 나머지 대기 신청은 자동 거절한다.
- 직원이 반납을 요청하고 관리자가 확인하면 반납이 완료된다.
- 자산번호별로 개별 장비와 대여·반납 이력을 관리한다.
- 대여 신청 시 반납 예정일을 필수로 입력한다.
- 반납 예정일이 지나도 반납이 완료되지 않은 대여는 연체로 표시한다. 연체로 인한 자동 반납이나 이용 차단은 하지 않으며 반납 요청을 허용한다.

## 자산 관리

- 직원은 장비를 조회하고 대여·반납을 요청한다.
- 관리자는 자산 등록·수정·삭제와 전체 대여 현황을 관리한다.
- 실제 데이터를 영구 저장한다.
- 자산 삭제는 이력을 보존하고 새 신청을 차단하는 보관 처리다. 대여 중이거나 반납 확인 대기 중인 자산은 반납 완료 후에만 삭제할 수 있다.
- 자산 정보는 자산번호, 장비명, 모델, 분류, 설명, 보관 위치, 상태로 구성하며 사진은 제외한다.
- 수리 중인 자산은 신청을 차단하고 기존 대기 신청은 자동 거절한다.

## 추가 업무 규칙

- 직원은 승인 전 본인의 신청을 취소할 수 있다.
- 관리자는 사유를 입력하여 대여 신청과 반납 요청을 거절할 수 있다. 반납 요청 거절 시 대여는 유지된다.
- 대여 연장과 미래 날짜 예약은 첫 버전에서 제외한다.
- 반납 예정일과 연체 판단은 KST 기준으로 처리하며 예정일 23:59:59까지를 기한으로 한다.
- 직원은 전체 장비와 본인 이력만 조회할 수 있다. 관리자는 전체 직원의 이력을 조회할 수 있다.
- 승인·거절·연체는 웹 화면에 표시하며 이메일·메신저 알림은 제외한다.

## 기술 방향

- SEO는 필요하지 않으며 프론트엔드는 정적 SPA로 구성한다.
- 백엔드는 Go로 구현하고 경량 구성을 우선한다.
- 낮은 동시 쓰기 빈도를 전제로 클라우드 운영 비용을 우선한다.
- 데이터베이스는 SQLite로 확정하며 Railway 영구 볼륨에 저장한다.
- 영구 볼륨을 사용하는 단일 인스턴스의 재배포 시 짧은 서비스 중단은 허용한다.
- 로컬 기본 구성은 React·TypeScript·Vite, Go·chi, modernc SQLite 드라이버와 goose 마이그레이션을 사용한다. 나머지 라이브러리는 해당 기능 구현 시 검증한다.

## 저장소와 배포

- 공개 GitHub 저장소를 만든다.
- main 직접 push와 강제 push를 차단한다.
- PR에서 빌드와 테스트를 자동 실행하고 필수 CI 통과 후 병합하도록 보호한다.
- main 병합 시 자동 배포한다.
- 프론트엔드는 Vercel에 배포한다.
- 사용자는 기존 Vercel 유료 계정을 사용한다.
- 백엔드와 데이터베이스는 Railway에 배포한다.
- DB 마이그레이션을 포함하여 main 병합 후 배포를 자동화한다.
- 개인 GitHub 계정의 공개 저장소를 사용한다.
- 최초 초기화 커밋은 main에 올리고 즉시 보호 정책을 적용한다. 이후 변경은 PR로만 병합한다.
