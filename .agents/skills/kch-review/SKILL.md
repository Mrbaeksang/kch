# KCH 코드 리뷰

관련 이슈와 실제 diff를 읽고 이번 변경으로 생긴 문제를 검토한다. 추정에 근거한 지적을 피한다.

## 관련 항목만 검토

- 직원이 관리자 API나 다른 직원 이력에 접근할 수 있는가? 사용자·역할·활성 상태를 서버에서 검증하는가?
- 자산별 진행 중 대여가 중복되는가? 승인·자동 거절·반납 완료가 트랜잭션으로 일관되게 처리되는가?
- 반납 확인 대기·연체가 용어집과 KST 기준에 맞고 수리·보관 규칙과 이력이 유지되는가?
- SQLite 마이그레이션과 재시작·재배포가 데이터를 보존하는가? 볼륨 접근과 실패 시 준비 상태가 올바른가?
- 개발 로그인·가상 계정·비밀키·운영 정보가 운영 경로나 공개 결과에 노출되는가?
- 입력·저장 실패와 세션 만료 안내를 이해할 수 있는가? 테스트가 변경한 동작의 실제 문제를 잡는가?

스타일·포맷은 기존 도구에 맡기고 무관한 코드를 수정하지 않는다.

## 결과와 수정

- 문제마다 위치·발생 조건·사용자 영향·수정 방향을 짧게 적고 미확인 사항을 명시한다.
- 문제가 없으면 ‘확인한 범위에서 발견한 문제 없음’으로 보고한다. 검토만으로 테스트 통과·운영 안전을 보장하지 않는다.
- 수정까지 요청받았다면 재현 테스트부터 고친다. 리뷰만 요청받았다면 코드를 임의로 수정하지 않는다.
- 별도 리뷰 도구·리뷰어를 실제 사용하지 않았다면 독립 리뷰를 받았다고 보고하지 않는다.
