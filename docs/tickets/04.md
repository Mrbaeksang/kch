## What to build

직원이 개별 자산의 반납 예정일을 입력하여 신청하고, 본인 신청 목록에서 상태를 확인하거나 승인 전 신청을 취소한다.

## 구현 정책과 현재 상태

- 반납 예정일은 KST 기준 오늘부터 허용하며 상한은 두지 않는다. 미래 대여 시작일 예약은 제공하지 않는다.
- 같은 직원·같은 자산의 승인 대기 신청은 한 건만 허용한다. 서로 다른 직원은 같은 자산에 신청할 수 있고 취소 후 재신청할 수 있다.
- PR #11 병합 후 feature/loan-requests 브랜치에서 TDD로 구현했다. 로컬 화면에서 신청·승인 대기·취소·재신청을 확인했다.
- 본인 목록·본인 대기 신청 취소·중복 및 동시 요청·사용 불가 상태·날짜 검증을 API와 실제 SQLite로 검사했다.
- 테스트 직원 A·B의 실제 로그인 경로로 서로의 신청 조회·취소 차단과 같은 장비 신청을 검증했다. main 반영 전이며 최신 PR과 CI 상태는 GitHub 이슈에서 확인한다. 관리자 승인 기능은 #6 범위다.

## Acceptance criteria

- [ ] 개별 자산 선택·반납 예정일 필수 입력·신청 결과 확인 화면을 API·SQLite와 연결한다.
- [ ] 같은 자산에 여러 직원의 대기 신청을 허용한다.
- [ ] 대여 중·수리 중·보관된 자산에 대한 새 신청은 서버에서 차단한다.
- [ ] 직원은 본인 대기 신청만 취소하고 다른 직원 신청의 조회·취소는 할 수 없다.
- [ ] 반납 예정일은 KST 날짜로 처리하고 브라우저 시간대에 따라 날짜가 바뀌지 않는다.
- [ ] 같은 직원의 동일 자산 중복 신청 방지와 유효한 신청 날짜 범위는 구현 전에 정책을 기록한다. 부모 명세에서 이미 확정된 것으로 간주하지 않는다.
- [ ] 실제 API·SQLite로 신청·취소·권한·상태 충돌을 검증하고 폼의 입력 오류 및 PR 빌드·테스트를 확인한다.
