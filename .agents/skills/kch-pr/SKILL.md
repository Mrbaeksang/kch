# KCH PR 규칙

## 제목과 본문

- 제목은 사용자에게 달라지는 점을 한국어 한 문장으로 쓴다. 예: `관리자가 장비를 등록하고 직원이 목록을 확인할 수 있게 한다`.
- 본문은 `.github/pull_request_template.md`를 읽고 따른다. 스킬 안에 양식을 중복 정의하지 않는다.
- 코드·파일 목록·내부 구현 용어 대신 사용자가 할 수 있는 행동을 설명한다. 판단에 꼭 필요한 기술 설명만 쉬운 말로 덧붙인다.
- ‘테스트 완료’ 대신 구체적인 행동과 결과를 쓴다. 예: ‘직원 계정으로 장비 수정을 요청하면 거절됩니다.’
- 화면 캡처는 필수가 아니다. 실제 화면에서 확인한 동작과 결과를 자연어로 적는다. 필요에 따라 이미지를 첨부할 경우 가상 정보만 사용한다.
- 로컬 테스트·GitHub CI를 구분하고 미검증·남은 일·설정·DB 변경·배포 영향을 알린다.
- 전체 범위를 완료할 때만 이슈 자동 종료 표현을 쓴다. 일부 구현은 `관련: #번호`로 연결한다.

## 제출과 병합

- 대표 이슈는 정확히 하나다. 이슈 1개당 브랜치 1개·PR 1개로 작업하고 다른 이슈의 변경은 별도 PR로 분리한다. 같은 이슈의 기존 열린 PR은 갱신한다. 참고 이슈는 본문에 설명할 수 있지만 함께 완료시키지 않는다.
- 한 PR에는 여러 목적별 작업 커밋이 있을 수 있다. 검토 후 Squash 병합하므로 main의 PR 단위 커밋과 작업 브랜치의 커밋 단위를 구분한다.
- push·PR 생성은 사용자가 요청한 범위에서 수행한다. 같은 브랜치의 기존 PR을 확인해 중복 생성하지 않는다.
- 준비 중이거나 완료 기준이 남아 있으면 초안 PR을 사용한다. 제목과 본문은 현재 최종 diff에 맞춰 갱신한다.
- main 보호·필수 CI를 우회하지 않는다. 현재 타인 승인 개수는 필수 조건이 아니며 팀 정책 변경이 승인되면 따른다.
- 병합은 별도 승인 범위에서 Squash 방식으로 수행하고 PR 제목을 사용한다. PR 생성 요청만으로 병합하지 않는다.
- PR 주소·CI 결과·미완료 사항을 보고한다. main 반영·배포는 확인한 경우에만 완료로 적는다.
