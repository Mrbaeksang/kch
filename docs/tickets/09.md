## What to build

운영자가 PR 자동 검사 후 병합하면 Vercel 프론트와 Railway Go 서버가 자동 배포되고 SQLite 마이그레이션이 적용된다. 재배포 데이터 보존과 백업 복원을 실제로 확인한다.

## 범위 변경

직원 등록·비활성화 관리 화면(#3)은 사용자 요청으로 제외한다. 로컬 개발은 직원 1명·관리자 1명으로 진행하고, 운영 허용 이메일과 관리자 지정은 배포 설정으로 연결한다. #3은 이 티켓의 선행 조건이 아니다.

## Google 로그인 최종 구현·검증

사용자 요청에 따라 #2에서 실제 Google 로그인 작업을 이 단계로 이관한다. 개발 단계의 역할 전환은 로컬 테스트 계정을 사용한다.

- [ ] Google OAuth·OIDC를 구현하고 서명·발급자·대상·만료·state·nonce·PKCE를 검증한다.
- [ ] 사용자에게 최초 관리자 지정 방식과 이메일을 받아 설정하며 첫 로그인 사용자를 자동 관리자로 만들지 않는다.
- [ ] 등록·활성 이메일만 Google 로그인할 수 있고 직원·관리자 역할을 모든 보호 API에서 검사한다.
- [ ] 운영 세션 저장 방식을 검증하고 로그인·로그아웃·비활성화에 따른 접근 종료를 확인한다.
- [ ] 운영 도메인 또는 동일 출처 프록시와 쿠키·CSRF·CORS·OAuth 콜백을 연결한다.
- [ ] 실제 Google 계정으로 로그인부터 신청·승인·반납까지 검증한다.
- [ ] 운영에서 테스트 로그인 설정과 경로가 비활성이고 테스트 계정이 운영 관리자나 허용 직원으로 자동 생성되지 않음을 확인한다.

## Acceptance criteria

- [ ] 기존 공개 저장소·main 보호·협업 규칙을 재사용하고 프론트·백엔드 빌드·테스트 검사 이름을 필수 보호 조건과 일치시킨다.
- [ ] 관리자 포함 직접 push·강제 push·main 삭제를 차단하고 CI 실패 PR의 병합을 막는다.
- [ ] main CI 성공을 확인한 동일 변경을 사용자의 유료 Vercel 계정과 Railway로 자동 배포한다. 실패한 CI는 운영 배포하지 않는다.
- [ ] Railway 단일 인스턴스의 영구 볼륨에 SQLite를 저장하고 짧은 재배포 중단은 허용한다.
- [ ] 볼륨 연결 후 HTTP 수신 전에 마이그레이션을 자동 실행한다. 실패 시 서버를 준비 완료로 표시하지 않는다.
- [ ] PR 검사·미리보기는 운영 DB와 비밀키를 사용하지 않으며 실제 직원 정보·DB·OAuth 비밀키를 저장소에 올리지 않는다.
- [ ] Google OAuth·관리자 지정·도메인·세션 설정과 배포 권한을 운영 환경에 연결하고 실제 로그인 및 장비 조회를 확인한다. 사용자 미제공 설정은 완료로 보고하지 않는다.
- [ ] 재시작·재배포 후 기록 보존, SQLite 일관된 백업·복원, 마이그레이션 실패와 앱 롤백 시 DB 호환성을 검증한다.
- [ ] 비개발자가 이해할 수 있는 배포 상태·필요 설정·복구 안내를 자연어로 남기고 실패가 정상 운영으로 표시되지 않음을 확인한다.
